How discovery handles blocked or unreachable pages

If an ordinary public request returns a likely access challenge, EdScanner can make one bounded retry with a real Chromium browser and feed the rendered page back into normal link detection. Connection-stack or certificate-chain failures have a separate two-page browser budget so a district homepage can lead to its board page. It does not retry rate limits, solve CAPTCHAs, rotate browser identities, or bypass robots policy. If recovery still fails, use Board Sources to add or correct the public source manually.

Discovery uses HTTPS only and IPv4 by default. An imported HTTP address is upgraded before it is requested. If the configured district homepage redirects to a different public HTTPS hostname, EdScanner accepts that website move as the new crawl base and records both addresses in the run ledger. Later cross-site redirects remain blocked. Known platforms must yield a canonical vendor URL and organization/tenant/site ID; one-off news, event, policy, media, and resource-manager pages cannot become working sources.

Default scope selects districts with no saved source. Choosing a specific source status instead selects districts with that saved status. Rediscover treats “Not yet checked” as “Any status” and reruns discovery from each selected district's public website; a specific status or platform narrows that rediscovery. A platform filter requires saved-source records, so combine it with Rediscover or a specific status.
